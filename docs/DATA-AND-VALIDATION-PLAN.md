# 팜로그 데이터 확보·평가 실행표

2026-09-07 · M0 이후 실제 데이터 도입 전에 사용하는 계획. 현재 실제 농가 데이터는 미확보. 동의/외부서비스 연결은 실행하지 않았다.

## 1. 최소 확보 묶음

1. 농가 1곳: 담당자와 연락은 별도 안전 위치, 제품에는 익명 코드.
2. 필지/시설 1~2개: 별칭, 작목, 작기, 실제 사용하는 면적 단위. 정확 주소/GPS/PNU는 M1 필수 아님.
3. 현재 사용하는 일지·서식 1종: 개인정보 가림, 발급기관·버전·필수 항목·제출 용도 확인.
4. 최근 작업 기록 10~20건: 원문과 농가가 확인한 정답을 분리. 사람이 추정한 값 표시.
5. 기록 검토자 1명: 틀린 필드·빠진 증거·서류 수용 여부 피드백.

**가족농가 1곳만으로는 제품시장 적합성 검증 아님.** 외부 농가와 실제 구매자의 반복 사용·결제를 별도로 확인한다.

## 2. 이벤트 및 평가 장부

### 이벤트 계약
- 키: event_id / synthetic 또는 실제 여부 / 익명 farm_id / parcel_id / crop_cycle_id.
- 일시: worked_at(작업일)과 created_at(기록일) 구분, timezone 보존.
- 내용: crop / work_type / inputs[] / amount / unit / 원문 참조.
- 품질: missing / source / extraction_version / human_reviewed / changed_fields.
- 감사: supersedes / evidence_refs[] / report_refs[] / policy_version.

M0의 source는 `synthetic_text` 또는 `human_reviewed_synthetic`. 실제 사용 시 다른 source와 별도 저장소로 분리해야 한다. 현재 `.local-data`는 데모용이므로 실제 자료를 넣지 않는다.

### 평가 케이스 계약
`case_id, split, farmer_slice, crop_slice, input_mode, raw_input_ref, context_version, expected, predicted, missing_expected, error_type, latency, human_seconds, model_cost`.

- expected는 농가/검토자 확인 정답. predicted와 다른 컬럼·파일로 유지.
- 공통 라벨 기준: 날짜·필지·작물·작업유형은 필수 4필드. 약제·수량·단위 등은 작업유형에 따른 별도 필수 규칙으로 확장.
- 추출이 쉬운 반복 문장만 추가하지 않는다. 모호한 표현·단위 누락·복수 작업·방언·잘못된 날짜·외부 규정 조회 실패를 포함.

## 3. 수집 동의와 운영 경계, 아직 미승인

수집 전 확인할 사항:
- 목적: 영농 기록·서류 준비. 모델 학습/평가 2차 이용은 별도 선택.
- 항목: 필요한 최소 범위. 주소·주민번호·계좌·정확 위치·음성은 이유 없이 수집하지 않음.
- 보관 위치/기간, 접근 담당자, 외부 LLM·STT 처리지역·수탁사, 백업·삭제 절차.
- 농가별 분리와 공유 대상 선택. 타 농가에게 기록이 보이지 않아야 함.
- 삭제 요청은 append-only라는 이유로 거부하지 않음. 원문 접근차단/삭제·감사메타데이터의 적법 보관은 정책 수립 필요.
- 임. 大 공간 참가정보·플레라플레로 주문정보를 합치지 않음.

이 문서는 개인정보 처리 정책 확정이나 동의서 대체가 아니다. 실제 데이터 도입은 위 결정 후 별도 승인한다.

## 4. 2주 concierge 장부와 성공/실패

농가별 매일 측정: 실제 농작업 있었는지 / 발화 수 / 자발 입력인지 / 재촉 횟수 / 입력·수정 소요시간 / 누락 / 서류 재사용 여부.

- 5명 중 3명이 두 주 모두 기록을 지속하면 원래 게이트 통과.
- 작업 없는 날은 실패 분모에서 빼되, 제외 기준을 사전에 고정.
- 외부 농가와 가족 농가 결과 분리.
- 총 100건은 목표일 뿐. 5농가×14일×하루1건=70건이고 실제는 더 적을 수 있음.
- 25건 탐색셋, 60건 개발셋, 100건 후보셋을 서로 다른 독립 실적처럼 합산하지 않음. 동일 사례 ID로 중복 추적.
- 유료 의향과 실제 결제, 무료 참여와 실제 재계약을 구분.

## 5. 기술 지표 정의

| 지표 | 분자/분모 | 목표 또는 해석 |
|---|---|---|
| 필수 필드 정확도 | 필수 4필드 exact match 수 / 전체 필수 4필드 수 | M2 제안 ≥95%, 전체 필드 ≥90% |
| 전체 필드 정확도 | 정답 일치 필드 / 채점 대상 필드 | null 비중도 함께 공개 |
| 과잉 추정률 | 정답 null인데 값 생성한 필드 / 정답 null 필드 | 낮을수록 좋음, missing별 따로 보고 |
| 완전일치율 | 모든 필수 필드 일치 event / event 수 | 쉬운 필드 평균으로 오류 은폐 금지 |
| 수정률 | 사람 수정 event / 검토 event | 수정 이유/필드도 공개 |
| 입력시간 | 녹음 시작~검토 저장까지 실제 시간 | 중앙값·p90, 20초 목표. 서버 처리시간과 다름 |
| 질문 횟수 | 기록당 보완 턴 | 1회 한 질문, 2턴 후 미완성 저장 선택 |
| 원문 근거율 | 근거 event ID 포함 보고서행 / 전체 행 | 목표100%, 사실의 진실성 보장 아님 |
| 규정 미확인률 | 조회오류·stale·매칭 모호 / 조회 요청 | 미확인을 안전/위반으로 바꾸지 않음 |
| 비용 | STT+LLM+저장+지원노무 / 활성농가 | 지원노무 포함 단위경제성 |

현재 30건 synthetic in-sample 회귀 결과는 위 실농가 목표를 충족했다는 증거가 아니다. 추출기와 함께 설계된 fixture이므로 일반화 평가가 아니다.

## 6. M2 evals 실험

1. 먼저 사람이 만든 baseline의 오류/시간 측정.
2. 모델 A/B를 같은 held-out 농가/기간에서 비교. 프롬프트·model ID·온도·schema 버전 기록.
3. 실제 모델 가용성·가격 확인 후 선택. 과거 문서 모델명이 현재 존재한다고 가정하지 않음.
4. timeout·malformed JSON·작목 미등록·복수작업은 null/사람검토로 돌아오는지 확인.
5. 음성 WER와 구조화 필드 정확도를 분리. STT만 잘해도 작업수량을 틀릴 수 있음.
6. 사진·센서·수확량 예측은 데이터 확보 후 별도 평가셋. 기록 정확도를 예측 성능으로 대체하지 않음.
7. 규정 adapter는 PSIS 원본/취소목록/버전/조회시각·라이선스를 확인한 뒤 snapshot 테스트. 공공 API 장애 테스트 포함.

## 7. 실농가 확장 전 차단 목록

- [blocked] 동의·보관·삭제·외부 처리 정책: 사용자와 현장 담당자 결정 필요.
- [blocked] 실제 필지·작목·서식: 농가 확인본 필요.
- [blocked] STT/LLM: 처리방식·예산·API 또는 로컬모델 환경 승인과 실제 발화 평가 필요.
- [blocked] 공식 규제 검증: API 권한·원본 응답·등록취소 갱신·약제 정합성 검토 필요.
- [blocked] 공식 문서: 기관 서식 버전·필드 매핑·검토자 수용성 확인 필요.
- [blocked] 모바일 실증: 기기·오프라인 동기화·권한·백업·농가별 격리 필요.

로컬 합성 데모의 검토·회귀는 위 차단 항목과 무관하게 실행할 수 있다.
