# 팜로그(FarmLog) 개발 계획

> 타겟: 한국 소·중농(개인) / MVP 코어: 음성·사진 → 영농일지 자동생성 / 스택 제약: 없음
> 작성일: 2026-09-03

---

## 0. 한 문장 정의

**"밭에서 한 마디 하면, 인증 서류가 된다."**
농민은 말하고 찍기만 한다. 구조화·검증·서류화는 에이전트가 한다.

---

## 1. 시장 현실 — 냉정하게

이미 영농일지 앱은 포화다. 새 일지 앱은 죽는다.

| 서비스 | 강점 | 빈틈 |
|---|---|---|
| 팜모닝(그린랩스) | 농민 90만+, 커뮤니티·시세·보조금 번들 | 일지는 폼 입력. 부가기능이라 깊이 얕음 |
| NH오늘농사 | 농협 구매내역 자동연동, 유통망 | 농협 회원 종속, UX 무거움 |
| 파밍노트 | AI 일지·자동장부·GAP 관리 | 가장 직접적 경쟁자. 입력 마찰은 여전히 폼 중심 |
| GAP 영농일지(풀무원) | 인증 양식 정합 | 사실상 전자 서식. 자동화 없음 |

**결론: "일지를 잘 적게 해주는 앱"은 시장이 없다. "적지 않아도 서류가 나오는 앱"에만 시장이 있다.**

### 진입 쐐기(wedge)
전체 농가가 아니라 **기록 의무가 실재하는 농가**부터. GAP·친환경(유기/무농약)·저탄소 인증 농가, 그리고 직불금 이행점검·농업경영체 등록 갱신 대상.
이유: 페인이 "귀찮음"이 아니라 "안 하면 인증 취소"다. 지불의사가 있다. 무료 경쟁자와 정면 충돌하지 않는다.

## 2. 차별화 축 3개

1. **입력 마찰 0** — 폼 없음. 음성 한 마디 또는 사진 한 장. 고령 농가가 실제로 쓸 수 있는 유일한 형태.
2. **일지 = 서류** — 입력이 그대로 GAP 영농일지 양식, 방제이력, 출하기록으로 출력. 재입력 없음.
3. **에이전트가 되묻는다** — 빠진 필드는 앱이 한 개씩 질문. 폼의 20칸을 대화 1~2턴으로 대체.

**진짜 해자는 3번이 아니라 "검증"이다.** → 아래 4.3

## 3. 사용자 시나리오 (MVP)

```
[밭에서, 장갑 낀 손]
농민: (녹음 버튼 길게 누르고) "오늘 3번 하우스 토마토에 스미치온 1000배로 쳤어"

에이전트:
  ├ STT → 텍스트
  ├ 추출 → {날짜: 2026-09-03, 필지: 하우스3, 작물: 토마토,
  │         작업: 방제, 농약: 스미치온(페니트로티온), 희석: 1000배}
  ├ 검증 → 농약안전정보시스템 조회
  │         ⚠️ "토마토 등록 농약이 아닙니다. PLS 위반 위험.
  │             등록 약제: A, B, C. 그대로 기록할까요?"
  └ 보완 → "살포 면적이 빠졌어요. 하우스3 전체(660㎡) 맞나요?" [예][수정]

→ 3초. 일지 저장 완료. GAP 서식·방제이력에 자동 반영.
```

## 4. 에이전트 아키텍처

파이프라인 5단. **각 단은 독립 함수**다. 프레임워크(LangChain 등) 쓰지 않는다 — 분기 5개짜리 파이프라인에 오케스트레이터는 부채다.

```
음성/사진 ──▶ ① 수집 ──▶ ② 추출 ──▶ ③ 검증 ──▶ ④ 보완질의 ──▶ ⑤ 저장/서류화
                            (LLM)     (규칙+API)     (LLM)
```

### 4.1 ① 수집
- 음성: CLOVA Speech(한국어 방언·노이즈 강함) 우선, Whisper 폴백. **온디바이스 STT는 사투리에서 무너짐 — 검증 전까지 채택 금지.**
- 사진: EXIF에서 촬영시각·GPS 추출 → 필지 자동 매칭(등록 필지 폴리곤 내 포함 여부). 이것만으로 필드 2개(날짜·필지)가 공짜.

### 4.2 ② 추출 에이전트 (LLM)
- 모델: `claude-sonnet-5`, structured output(tool schema)으로 강제.
- 입력: STT 텍스트 + 사용자 컨텍스트(등록 필지 목록, 재배 작물, 최근 30일 일지 요약).
  → **컨텍스트가 정확도를 만든다.** "3번 하우스"를 해석하려면 필지 목록이 프롬프트에 있어야 한다.
- 출력: `WorkLog` JSON. 불확실한 필드는 값 대신 `null` + `missing_reason`. **환각 금지 규칙: 들리지 않은 값은 절대 추정하지 않는다.**
- 분류·라우팅 등 가벼운 판단은 `claude-haiku-4-5`로 내려 비용 절감.

### 4.3 ③ 검증 에이전트 (LLM 아님 — 규칙 + 공공 API)
**여기가 제품의 심장이다.** LLM에게 농약 안전기준을 맡기지 않는다. 결정론적 조회만 쓴다.

- 농촌진흥청 농약안전정보시스템(PSIS) OpenAPI → 작물-농약 등록 여부, 희석배수, 살포 횟수, **수확 전 마지막 사용일(PHI)**
- 국가농작물병해충관리시스템(NCPMS) API → 병해충 도감·방제법
- 검증 룰:
  - `작물 × 농약` 미등록 → **PLS 위반 경고 (차단이 아니라 경고 + 기록)**
  - 희석배수 기준 이탈 → 경고
  - 살포 횟수 초과 → 경고
  - 예상 수확일 − 마지막 살포일 < PHI → **출하 경고 알림 예약**
- 캐시: 농약 DB는 월 1회 동기화 후 로컬 SQLite. 밭에서 오프라인이어도 검증된다.

> 이 기능 하나가 유료 전환의 근거다. "잔류농약 검출로 출하 반려"는 농가에 수백만 원 손실이다.

### 4.4 ④ 보완 질의 에이전트
- 필수 필드가 빈 경우에만 발동. **한 번에 한 질문, 최대 2턴.** 3턴 넘어가면 사용자가 앱을 던진다.
- 선택지 버튼 우선(타이핑 강요 금지), 과거 이력에서 기본값 제시("지난번처럼 660㎡?").

### 4.5 ⑤ 서류화 에이전트 (Phase 2)
- 축적된 `WorkLog` → GAP 영농일지 서식, 방제이력부, 출하기록, 경영체 등록 갱신용 재배현황 → PDF/XLSX.
- LLM 아님. 템플릿 렌더링. **여기에 LLM 쓰면 서류가 틀린다.**

## 5. 데이터 모델 (최소)

```sql
farms        (id, user_id, name)
parcels      (id, farm_id, name, pnu, area_m2, geom)      -- 필지. geom은 사진 GPS 매칭용
crops        (id, parcel_id, crop_code, variety, planted_at, expected_harvest_at)
work_logs    (id, parcel_id, crop_id, worked_at, work_type, memo,
              raw_input, source, confidence, created_at)   -- raw_input 원문 보존 = 감사 대비
inputs       (id, work_log_id, kind, product_code, name, amount, unit, dilution)
attachments  (id, work_log_id, storage_path, taken_at, lat, lng)
validations  (id, work_log_id, rule, severity, message, checked_at)
```

`raw_input`(원본 음성 텍스트) 보존은 타협 불가. 추출이 틀렸을 때 되돌릴 근거이자, 모델 개선용 데이터셋이다.

## 6. 기술 스택

| 레이어 | 선택 | 이유 |
|---|---|---|
| 앱 | Expo (React Native) | iOS/Android 동시. 카메라·마이크·백그라운드 동기화 네이티브 접근 필요 → PWA 탈락 |
| 로컬 DB | expo-sqlite | **오프라인 우선.** 밭은 LTE가 안 터진다. 로컬 저장 → 큐 → 동기화 |
| 백엔드 | Supabase (Postgres + Auth + Storage + RLS) | 서버 코드 최소화. PostGIS로 필지 폴리곤 그대로 처리 |
| LLM | Claude API (`claude-sonnet-5` 추출 / `claude-haiku-4-5` 분류) | structured output, 한국어 강함 |
| STT | CLOVA Speech | 한국어 방언·고령층 발화 |
| 공공데이터 | PSIS, NCPMS, 기상청 단기예보 | 검증·알림의 근거 |
| 서버 로직 | Supabase Edge Function 1개 | 파이프라인 전체가 함수 하나. API 키를 앱에 넣지 않기 위한 최소 서버 |

**만들지 않는 것:** 자체 인증서버, 자체 파일스토리지, 마이크로서비스, 관리자 웹(Supabase Studio로 충분), 자체 병해충 모델.

## 7. 로드맵

### Phase 0 — 검증 (2주, 코드 0줄)
- 인증 농가 10명 인터뷰. **"작년 영농일지 보여주세요"** — 실제로 쓰는지가 전부다.
- 콘시어지 테스트: 카톡으로 음성 받아 수동으로 일지 만들어 전달. 5명 × 2주.
- **게이트: 5명 중 3명이 2주 내내 보내면 진행. 아니면 타겟 재설정.**

### Phase 1 — MVP (6주)
| 주 | 산출물 |
|---|---|
| 1 | Supabase 스키마 + Expo 셸 + 로그인. 필지/작물 등록 |
| 2 | 음성 녹음 → STT → 텍스트 확인 화면 (추출 없이 원문만) |
| 3 | 추출 에이전트 + structured output. 정확도 측정 하네스(라벨 100건) |
| 4 | 보완 질의 UI + 일지 저장 + 목록/수정 |
| 5 | 오프라인 큐·동기화, 사진+EXIF 필지 매칭 |
| 6 | 베타 20농가 배포, 계측(입력 소요시간·필드 정확도) |

**Phase 1 완료 기준: 일지 1건 20초 이내, 추출 필드 정확도 90%+**

### Phase 2 — 해자 (4주)
- 농약 검증(PSIS 연동 + 로컬 캐시), PLS 경고, PHI 출하 알림
- GAP 영농일지 서식 PDF 출력
- 유료화 시작

### Phase 3 — 확장 (이후)
- 병해충 사진 진단(자체 학습 X, NCPMS 도감 + 비전 모델 조합)
- 작목반/컨설턴트 대시보드 (B2B — 진짜 매출은 여기)
- 경영장부·소득 리포트

## 8. KPI

| 지표 | 목표 | 왜 |
|---|---|---|
| 일지 1건 입력 시간 | ≤ 20초 | 마찰 0이 제품 전체의 전제 |
| 추출 필드 정확도 | ≥ 90% (필수 필드 ≥ 95%) | 이하면 신뢰 붕괴, 사용자가 폼으로 회귀 |
| 보완 질의 턴 수 | 평균 ≤ 1.2턴 | 되묻기가 많으면 폼보다 느리다 |
| W4 리텐션 | ≥ 40% | 농사는 매일. 안 쓰면 죽은 앱 |
| 주당 일지 수/농가 | ≥ 4건 | 서류가 나올 만큼의 밀도 |
| 유료 전환(인증농가) | ≥ 15% | Phase 2 이후 |

## 9. 수익 모델

- **개인 Free**: 월 30건, 일지·검증
- **개인 Pro (연 39,000원)**: 무제한, 인증 서식 출력, PHI 알림, 백업
  → 인증 대행 컨설팅 비용(수십만 원) 대비 압도적으로 싸다. 가격 저항 낮음.
- **B2B (실제 수익)**: 작목반·인증기관·지자체·수출 바이어 대시보드. 시트당/농가당 과금.
  개인 앱은 데이터 수집 채널이고, 돈은 그 데이터를 봐야 하는 쪽이 낸다.

## 10. 리스크와 대응

| 리스크 | 심각도 | 대응 |
|---|---|---|
| 팜모닝이 같은 기능을 무료 번들 | 높음 | 커뮤니티로 경쟁 안 함. 인증·규제 준수 깊이로 방어. B2B 계약이 진짜 락인 |
| 고령층 발화 STT 정확도 | 높음 | Phase 1에서 실측. 60대+ 20명 발화 벤치마크 필수. 미달 시 사진+버튼 입력으로 축 전환 |
| 농약 DB 최신성 오류 → 오정보 책임 | 높음 | "참고용, 최종 확인은 라벨" 고지 + 데이터 출처·갱신일 화면 표기. 차단 아닌 경고로만 |
| LLM 비용 | 중간 | 일지 1건 ≈ 2~4K 입력 토큰. 컨텍스트 캐싱 + 분류는 haiku로. 단가는 실사용 청구서로 검증 |
| 농민 앱 획득 비용 | 중간 | 개인 광고 금지. 작목반·인증기관·농기센터 단위 하향 배포 (B2B2C) |
| 계절성 (겨울 이탈) | 중간 | 비수기엔 결산·서류·내년 계획으로 용도 전환 |

## 11. 개발 에이전트 세팅 (레포 초기)

프로덕트 에이전트와 별개로, 이 레포에서 쓸 개발 보조 세팅:

- `CLAUDE.md`: 도메인 용어집(필지/PNU/PHI/PLS/방제/약제 등), 스키마 요약, "LLM은 추출·질의에만, 검증·서류는 결정론적으로" 원칙 명시
- 정확도 회귀 테스트: 라벨링된 발화 100건 → 추출 결과 diff. **프롬프트 수정할 때마다 돌린다.** 이게 없으면 프롬프트 튜닝이 도박이 된다
- `.env.example` + Supabase 마이그레이션 파일로 환경 재현
