# 팜로그 농민용 앱 리뉴얼

2026-09-07 · 사용자 피드백을 우선 반영한 제품 변경

## 무엇을 잘못 만들었나

이전 M0는 고정 합성 예시를 구조화한 뒤 사람이 판정하는 관리자 검토 데스크였다. 사용자가 요청한 서비스는 **현장에서 말·사진·대화로 기록하면 영농일지를 작성해주는 농민용 앱**이다. 입력 도구·대화·실제 모델·일지 작성이라는 본질이 이전 M0에서 빠져 있었다.

77개 회귀 통과는 그 좁은 M0의 기술 검사일 뿐, 농민용 제품 완성도가 아니다. 이전 성과를 새 앱 성과처럼 합산하거나 완료 주장에 사용하지 않는다.

## 이번 사용자의 정정에 따른 우선순위

1. **기록의 시작**: 홈에서 큰 녹음 버튼, 사진 촬영/선택, 글로 대화하기.
2. **자연스러운 기록**: 미리 만든 fixture만 고르는 방식 폐기. 실제 자유 텍스트·사용자가 고른 미디어 처리.
3. **대화형 보완**: 앱이 모르는 것만 한 번에 하나 질문. 날짜·밭·작물·작업을 수십 개 폼으로 강요하지 않는다.
4. **일지로 작성**: 대화·원문·첨부를 바탕으로 작업일·필지·작목·자재·작업내용 칸을 채운다.
5. **마지막 확인**: 농민이 내용을 읽고 확정한다. 기존 append-only·정정·중복 방지 원칙은 뒷단에 둔다.
6. **다시 쓰기**: 날짜/밭별 기록 조회, 상세 확인, 정정, 기간별 인쇄/CSV.

## 기존 자료의 해석

사용자가 지정한 `_etc/tmp/farm-log-claude-project/`를 참조용 입력으로 읽었으며 원문은 변경하지 않는다.

- 01 SSOT: 음성/사진/텍스트·구조화·기록조회·행정초안.
- 08 제품계획: 말하고 찍는 농민, 문서 노동 제거.
- 09 실행계획: 녹음과 실제 농민 현장 flow, 오프라인 입력.
- 10 UI 스펙: 홈 녹음, 확인 카드, 보완 질문, 목록, 상세, 필지설정.
- 11·13: 입력-정규화-저장-조회-초안의 공통 구조, 근거 연결.
- 06·07: 당시 M0의 제한 기록. **새 구현의 범위를 영구적으로 합성데이터만으로 제한하는 지시로 적용하지 않는다.**

문서 사이 '서류 출력은 Phase2'와 사용자 현재 '일지 양식으로 작성'이 충돌할 때 현재 사용자 요구를 우선해 일지 출력을 포함한다. 규제 판정과 인증신청은 여전히 별개다.

## 구현 형태

- 모바일 우선 PWA: 설치 가능한 웹앱 shell과 매일 쓰는 농민용 UI. 네이티브 iOS/Android 앱스토어 바이너리가 아님.
- 로컬 Mac backend: `src/app-server.mjs` · `http://127.0.0.1:8880/`.
- 로컬 Ollama: qwen3:4b 구조화·대화 맥락 처리. cloud/remote 모델 거부.
- 사진: 선택·촬영·미리보기·원본첨부 + Tesseract.js 한국어/영어 WASM OCR. 사진 속 질병이나 작물 상태를 진단하는 비전 모델은 아님.
- 음성: 브라우저 MediaRecorder 로컬 녹음·재생 + Whisper tiny multilingual q8 WASM STT. 인식 후보를 입력창에 보여주고 사용자 수정값을 기준으로 작성한다. 실제 가용성은 최종 검증 리포트로 확인.
- 저장: 새 `.local-data/farmer-app/`에 보관. M0 원장·합성데이터와 혼합하지 않음.
- 끊김: 브라우저 IndexedDB 임시 보관과 사용자 재전송. 원문을 잃지 않는 것이 원칙. 실제 밭에서 비행기모드/휴대폰 데이터 통신 테스트는 별도.

기술 계약과 API는 [FARMER-APP-CONTRACT.md](FARMER-APP-CONTRACT.md), 실제 검증은 `evidence/FARMER-APP-VERIFICATION.md`가 정본이다.

## 일지 양식의 근거

[농식품부 공익직불제 영농일지 게시물](https://mafra.go.kr/bbs/gong/447/565634/artclView.do)의 표준 영농일지 PDF(13쪽)를 내려받아 2쪽 작성안내와 3쪽 빈 양식을 확인했다.

| 정부 예시 항목 | 앱의 데이터 | 작성 원칙 |
|---|---|---|
| 작업일 | worked_at | 입력일과 구분, 상대날짜는 선택 작업일 기준 |
| 필지 | parcel_id + parcel_name snapshot | 별칭을 등록 필지에 매칭, 정확주소/PNU 필수 아님 |
| 작목 | crop | 발화 또는 농민 확인값, 필지정보만으로 임의 확정 안 함 |
| 날씨 | weather | 사용자가 말하지 않으면 미기재 |
| 농약/비료 구입·사용 | inputs[action/kind/name/quantity/unit] | 구입과 사용을 구분, 라벨 사진=사용사실 아님 |
| 작업단계·작업명 | work_type | 복수작업 내용도 보존 |
| 세부작업내용 | details + 면적/시간/인원/희석/수확 | 말하지 않은 값을 만들어내지 않음 |

[2021 작성예시 안내](https://www.mafra.go.kr/bbs/gong/447/327120/artclView.do)는 정해진 양식이 있는 것은 아니라고 설명한다. 앱의 출력은 **정부 작성예시 항목을 반영한 자체 재구성 영농일지**다. 특정 인증기관의 제출 양식과 완전히 같거나 공익직불·GAP·유기 인증을 보장한다고 표시하지 않는다.

## 시나리오별 완료 판단

| 시나리오 | 사용자가 해야 하는 일 | 앱이 해야 하는 일 |
|---|---|---|
| 간단한 글 기록 | '오늘 3번 하우스 토마토 물 30분 줬어' | 관수·30분을 실제 모델로 정리, 일지 초안 |
| 빠진 작물 | '오늘 윗밭에 물 줬어' | 작물 한 가지 질문, 답변을 이전 기록에 연결 |
| 자세한 챗봇 | 작업 → 면적 → 수확량 추가·정정 | 전체 대화와 이전 확정값을 연결해 갱신 |
| 사진 | 사진 선택 후 어떤 작업인지 설명 | OCR을 참고로만 사용, 사진과 원문을 일지에 연결 |
| 음성 | 녹음 후 원문 확인 | 파일 보존, STT, 필요 시 직접 수정 경로 |
| 일지 완성 | 확인하고 저장 | 영농일지 양식으로 표시, 날짜·필지 조회 가능 |
| 정정 | 이전 기록을 열어 수정 | 원본은 보존, 새 정정 기록으로 연결 |
| 출력 | 기간·필지 선택 후 인쇄 | 검토한 기록만 A4 양식/CSV 작성 |

## 제한을 제품 뒤로 숨기지는 않되, 제품을 제한 안내로 대체하지 않기

- 모델 실패는 'AI 처리 실패·임시 기록 보존'으로 표시하고 입력을 버리지 않는다.
- 규제 판정 미검증 안내는 기록/출력의 보조 정보로 둔다. 홈의 주제가 합성검증·판정이 되지 않게 한다.
- 아직 실농가 실증·다중사용자 보안·실제기기 PWA 설치·상용 데이터정책을 완료한 것은 아니다.
- 음성·사진·대화의 로컬 보관과 외부전송 없음 안내를 첫 시작에 보여준다. 기존 사용자 자료를 자동으로 읽어 앱에 넣지 않는다.
- 실제 데이터 삭제·보관정책·농가별 권한이 없는 상태로 서비스 공개하지 않는다.

## 다음 제품 결정

실제 농가의 서식 1종과 실제 휴대폰을 기준으로 오프라인·입력시간·STT 정정률을 검증한다. 이 필요조건을 이유로 앞단 서비스를 다시 빈 데모로 축소하지 않는다.
