## 0.3 트랙 A — 인터뷰 & 콘시어지

### 모집 (Day 1~3, 목표 10농가)

접근 순서. 위에서부터 뚫는다.

1. **지역 농업기술센터 / 농업인 교육 담당자** — 인증 농가 명단을 실제로 쥐고 있다
2. **GAP·친환경 인증기관 컨설턴트** — 서류 페인을 대신 겪는 사람. 가장 말이 잘 통한다
3. **작목반·법인 단위** — 한 명 뚫으면 5명이 딸려온다
4. 농민 밴드·카페 (전환율 최악, 마지막 수단)

> 개별 농가에 콜드로 접근하지 않는다. **중개자를 통해야 인터뷰가 잡힌다.**

### 인터뷰 질문 (1인 40분)

핵심은 의견이 아니라 **증거**다. 첫 질문이 전부다.

1. **"작년 영농일지 좀 보여주세요."** — 없으면 "왜 안 쓰셨어요?"
2. 마지막으로 기록한 게 언제인가요?
3. 방제하고 나면 뭘, 어디에 적으세요? (수첩 / 달력 / 카톡 나에게 / 안 적음)
4. 하루 중 언제 적으세요? 밭에서, 아니면 저녁에 들어와서?
5. 인증 갱신·이행점검 서류는 어떻게 준비하셨어요? **몇 시간 걸렸어요?**
6. 누가 대신 써준 적 있나요? (컨설턴트 / 자녀 / 농기센터)
7. PLS나 잔류농약으로 문제 겪은 적 있으세요? 주변 사례는요?
8. 지금 깔려 있는 농사 앱 좀 볼게요. 무엇 때문에 여세요?

**판정 신호**
- ✅ "수첩에 적어요" / "카톡 나에게 보내요" → 대체할 대상이 있다
- ✅ "서류 만들 때 3일 걸렸어요" → H2 성립
- ❌ "안 적어요, 다 기억해요" → 이 농가는 타겟이 아니다
- ❌ 8번에서 앱을 열어보지도 못함 → 스마트폰 리터러시 하한선. 비중을 세라

### 콘시어지 프로토콜 (Day 4~17, 5농가 × 14일)

```
농민 ──카카오톡 1:1──▶ 음성 메시지 "오늘 3번밭 고추 순 쳤어"
                          │
                    (수동 처리, 우리가 사람 손으로)
                          │
                     ◀── 저녁 9시, 일지 요약 카드 이미지 1장
```

**규칙 4개 — 이걸 어기면 데이터가 오염된다.**

1. **먼저 리마인드하지 않는다.** 자발성이 측정 대상이다. "오늘 기록하셨어요?"를 보내는 순간 리텐션 숫자가 거짓이 된다.
2. 1:1 채팅만. 오픈채팅방은 서로 눈치를 보게 만든다.
3. 회신은 하루 1회 저녁 일괄. 실시간 응답은 사람이 붙어 있다는 걸 들키고, 제품 경험과 달라진다.
4. 되물음은 **하루 최대 1개**. 실제 앱의 제약(최대 2턴)을 사람이 흉내 낸다.

**이건 인터뷰가 아니라 데이터셋 수집이다.** 14일치 발화가 그대로 Phase 1 W3의 **라벨 100건**이 된다. 그래서 시트를 처음부터 제대로 만든다.

### 기록 시트 스키마

| 컬럼 | 예시 | 용도 |
|---|---|---|
| `ts` | 2026-09-05 14:22 | 발화 시각 → 언제 기록하는지 |
| `farmer_id` | F03 | |
| `raw_text` | "3번밭 고추 순 쳤어" | **라벨 데이터 원문** |
| `worked_at` / `parcel` / `crop` / `work_type` | 2026-09-05 / 3번밭 / 고추 / 적심 | 필수 4필드 정답 |
| `product` / `amount` / `dilution` / `area` | – / – / – / – | 선택 필드 정답 |
| `missing` | area | 누락 필드 |
| `we_inferred` | worked_at(=발화일) | **우리가 추정한 것.** 모델도 여기서 틀린다 |
| `asked` | Y/N | 되물음 필요 여부 |
| `manual_sec` | 95 | 사람이 처리한 시간 |

`we_inferred` 컬럼이 이 시트의 숨은 핵심이다. 사람이 무의식적으로 채운 값이 곧 **모델에게 컨텍스트로 줘야 할 정보**다.

### 게이트 판정 (Day 18)

| # | 기준 | 통과선 |
|---|---|---|
| G1 | 지속성 — 14일 중 8일 이상 발화를 보낸 농가 | 5명 중 **3명** |
| G2 | 자발성 — 리마인드 없이 온 발화 비율 | **≥ 70%** |
| G3 | 추출 가능성 — 되물음 1회 이내로 필수 4필드가 채워진 발화 | **≥ 80%** |
| G4 | 서류 페인 — 인증·이행점검에 연 4시간 이상 쓴다고 답한 농가 | 10명 중 **6명** |
| G5 | 지불의사 — "연 39,000원이면 쓰시겠어요?" 즉답 예 | 5명 중 **2명** |

- **5개 중 4개 통과 → Phase 1 진행**
- **G3 단독 실패 → 음성 축 재검토.** 사진+버튼 입력으로 코어를 바꾼다
- **G1·G2 실패 → 타겟 재설정.** 개인 농가가 아니라 컨설턴트를 사용자로 놓는 안으로 전환
- 3개 이상 실패 → 중단

## 0.4 트랙 B — API 스파이크 (Day 1 신청, Day 8~9 실행)

**Day 1에 반드시 신청한다.** 공공 API 키 승인에 며칠이 걸리고, 이게 늦으면 Phase 0 전체가 밀린다.

- 농촌진흥청 **PSIS** (농약안전정보시스템) — 안전사용기준
- 농촌진흥청 **NCPMS** (병해충관리시스템) — 도감·방제법

### 확인 체크리스트

| # | 확인 항목 | 안 되면 |
|---|---|---|
| 1 | 작물코드 × 농약품목 **등록 여부** 조회가 되는가 | 검증 기능 불성립 → **제품 재설계** |
| 2 | 응답에 희석배수·살포횟수·**수확 전 사용일(PHI)**이 포함되는가 | PHI 알림 삭제. 해자의 절반이 사라진다 |
| 3 | **상표명 → 품목명 매핑**이 되는가 (스미치온 → 페니트로티온) | 아래 참조 ⚠️ |
| 4 | 전량 덤프가 가능한가 / 호출 쿼터는 | 오프라인 캐시 불가 → 밭에서 검증 못 함 |
| 5 | 데이터 갱신 주기 | 동기화 주기 결정 |

> ⚠️ **3번이 이 스파이크의 진짜 목적이다.**
> 농민은 절대 "페니트로티온"이라고 말하지 않는다. "스미치온", "그 파란 통"이라고 한다.
> API가 상표명 검색을 지원하지 않으면 → 상표명 사전을 자체 구축하거나, LLM 매핑 + 사용자 확인 UI를 넣어야 한다. **이건 Phase 2가 아니라 지금 알아야 할 사실이다.**

# Phase 1 — MVP (6주)

## 1.0 완료 정의

> **실제 농민이 밭에서 말한 것이, 20초 안에, 90% 정확도로 일지가 된다.**

농약 검증도, 서류 출력도 Phase 1에 없다. 이 한 문장만 증명한다.

## 1.1 주차별 계획

### W0 — 셋업 (2일, Phase 0과 병행)
- Expo 앱 부팅, Supabase 프로젝트, `.env.example`
- `CLAUDE.md`: 도메인 용어집(필지·PNU·PHI·PLS·방제·약제·적심·관주), 스키마 요약, 원칙 한 줄 — *"LLM은 추출과 질의에만. 검증과 서류는 결정론적으로."*

### W1 — 기반: 필지와 작물
- 스키마 마이그레이션 7테이블 + RLS
- **카카오 로그인.** 이메일+비밀번호는 이 사용자층에서 이탈 지점이다
- 필지 등록: 주소 검색 또는 지도 핀 + 면적 직접 입력
  - **폴리곤 그리기는 만들지 않는다.** 사진 GPS 매칭은 핀 + 반경으로 충분하다
- 작물 등록: 작목 선택 + 정식일

**DoD** — 실기기에서 필지 2개·작물 1개 등록 후 재로그인 시 유지된다.

### W2 — 음성에서 텍스트까지
- 홀드-투-토크 녹음 버튼 (탭 토글 아님 — 장갑 낀 손은 오조작한다)
- 업로드 → CLOVA Speech → 원문 표시 · 수정 · 저장
- **이 시점에서 앱은 이미 "농사 음성 메모장"으로 쓸 수 있다.** 베타 농가 5명에게 조기 배포해 W3~W5 내내 실사용 발화를 계속 받는다

**DoD** — 30초 발화가 5초 안에 텍스트로. **60대 이상 발화 20건 WER 실측치를 문서에 기록한다.** (리스크 목록 2번의 조기 판정)

### W3 — 추출 에이전트 ★ 최대 난관
- Edge Function 1개: 컨텍스트 조립 → `claude-sonnet-5` structured output → `WorkLog`
- 컨텍스트에 반드시 넣을 것 — Phase 0 `we_inferred` 컬럼이 알려준 그 정보들:
  - 등록 필지 목록(별칭 포함: "3번밭", "윗밭")
  - 현재 재배 작물
  - 최근 30일 일지 요약
  - 오늘 날짜
- 평가 하네스: `npm run eval` → Phase 0 라벨 100건에 대한 **필드별 정확도표**
- **프롬프트를 고칠 때마다 돌린다.** 없으면 튜닝이 도박이 된다

**DoD** — 필수 4필드(날짜·필지·작물·작업유형) ≥ 95%, 전체 필드 ≥ 90%.

**미달 시** — W4로 넘어가지 않고 튜닝에 1주를 더 쓴다(W5 버퍼 소진). 2주 후에도 90% 미달이면 **음성 축을 접고 사진+버튼 입력으로 전환한다.**

### W4 — 확인과 보완
- 추출 결과를 **편집 가능한 확인 카드**로 제시. 자동 저장하지 않는다 — 사용자가 승인해야 저장된다
- 누락 필드만 한 개씩 질문. **최대 2턴.** 선택지 버튼 우선, 과거 이력에서 기본값 제시
- 일지 목록 · 수정 · 삭제

**DoD** — 되물음 평균 ≤ 1.2턴, 발화 시작부터 저장까지 ≤ 20초.

### W5 — 현장 내구성
- **오프라인 우선**: expo-sqlite에 먼저 저장 → 온라인 복귀 시 큐 동기화
  - 충돌은 last-write-wins. `ponytail: 1인 1기기 가정. 협업 편집 생기면 그때 CRDT`
- 사진 촬영 → EXIF 촬영시각·GPS → 필지 핀 반경 내 매칭 → 날짜·필지 자동 채움
- 실기기 테스트: 비행기모드, 저전력 모드, 장갑, 직사광선 하 화면

**DoD** — 비행기모드로 일지 3건 작성 → 네트워크 복귀 후 3건 모두 동기화.

### W6 — 베타 20농가
- TestFlight / Play 내부테스트 배포
- 계측 이벤트: `log_started` → `stt_done` → `extract_done` → `question_turns` → `log_saved`, 각 구간 소요시간
- **핵심 지표: 사용자 수정률** — 확인 카드에서 사용자가 고친 필드 수 / 전체 필드 수. 실사용 정확도의 프록시다
- 리텐션은 Supabase SQL 뷰로 충분. **대시보드 툴을 붙이지 않는다**

**DoD** — 7일간 일지 100건 이상 수집, 사용자 수정률 < 10%.

> 전부 Phase 2 이후. **"20초·90%"가 안 되면 나머지는 전부 무의미하다.**

## 1.4 리스크 대 일정

6주 중 **W3 하나가 전체 리스크의 절반**이다. W5의 오프라인·사진 작업은 기술적으로 지루하지만 확실하고, W1·W4는 평범한 CRUD·UI다. 일정이 밀리면 W5를 잘라 W3에 붙인다 — 오프라인 동기화는 베타 20농가에게 1주 늦어도 되지만, 추출이 틀리면 베타 자체가 무의미하다.
