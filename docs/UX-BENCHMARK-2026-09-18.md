# 팜로그 농민 앱·연동 관리자 UX 벤치마크

- 조사 기준일: 2026년 9월 18일(KST)
- 목적: 농민이 가볍게 기록하고 관리자가 **같은 기록**을 확인하는 로컬 MVP의 재사용 가능한 설계 근거 마련
- 문서 성격: 공식 공개 문서에 근거한 정성 비교와 FarmLog 설계 제안. 경쟁사 성능 평가·고령자 사용성 실험·구현 완료 보고서가 아니다.
- 연결 문서: [MVP 구축 계획](MVP-FOUNDATION-PLAN.md), [기존 농민 앱 계약](FARMER-APP-CONTRACT.md), [기존 리뉴얼 배경](APP-RENEWAL.md)

## 1. 결론: 팜모닝 → Farmable → 농업ON 순으로 참고한다

**팜모닝의 익숙한 기록 언어와 월별 회고, Farmable의 기록·조회·출력 연결, 농업ON의 내 기록 중심 카드 구성을 선택적으로 가져온다.** 완성된 종합 포털을 복제하는 것이 아니라, `기록하기 → 확인하고 저장 → 관리자 확인`이라는 한 줄의 흐름을 만든다.

| 참고 순위 | 서비스 | 가장 먼저 참고할 부분 | 순위 근거 | 그대로 복제하지 않을 부분 |
|---|---|---|---|---|
| 1 | 팜모닝 | 한국어 영농일지 진입·기록하기·월별 작업 현황 | 한국 농민 대상의 용어와 기록·조회 흐름이 이번 농민용 첫 화면에 직접적 | 공개 커뮤니티·질문·시장 기능을 기록 홈의 동급 메뉴로 확대 |
| 2 | Farmable | 모바일·웹 계정 연결, 필터한 기록 출력, 관리 포털 | 농민 입력과 관리자의 후속 확인을 연결할 때 참고 가치가 큼 | Enterprise 다농가·초대·권한·작업배정 전체를 단일 농장 로컬 MVP에 이식 |
| 3 | 농업ON | 내 일지/이웃 일지 구분, 사진·글 카드, 달력·통계 보조 보기 | 국내 영농일지와 행정 관련 장기 맥락의 보조 참고 | 랭킹·영농스타·입출금장부를 매일의 기록보다 앞세움 |

이 순위는 시장점유율·완성도·매출·속도 순위가 아니다. **이번 MVP 과업과의 적합성 순위**이며 점수나 가중치로 측정한 결과가 아니다.

## 2. 조사 방법과 증거 한계

### 2.1 확인 수준

- 공식 운영 계정의 기능 안내와 공식 도움말을 읽었다. 공개 홈페이지는 현재 노출되는 기록·질문 콘텐츠의 존재를 확인하는 보조 근거로만 썼다.
- 로그인 뒤 기록 작성·저장·출력을 직접 수행하지 않았다. 계정별 기능 차이, 실제 화면의 모든 필드, 로딩 속도, 오류 복구, 오프라인 동작은 미확인이다.
- 실제 농민·고령자·장갑 사용·야외 햇빛 조건의 사용성은 측정하지 않았다. “농민에게 쉽다”는 결론을 성과로 주장하지 않는다.
- 안내문에 등장하는 기능의 존재와 배치를 참고한다. 경쟁사 스크린샷·아이콘·CSS·문구·코드를 복사하지 않는다.
- 댓글은 대표성 있는 조사 표본이 아니므로 경쟁사 결함을 입증하는 근거로 쓰지 않는다.
- 공식 문서의 과거 개편 사유는 **개편 전 상태 설명**이다. 현재도 문제가 지속된다는 증거로 취급하지 않는다.

### 2.2 객관적으로 확인 가능한 정성 기준

| 기준 | 확인 질문 | 자료에서 판별 가능한 것 | 이 조사로 판별할 수 없는 것 |
|---|---|---|---|
| 기록 진입의 명확성 | 기록 메뉴·작성 버튼 안내가 있는가? | 메뉴 이름과 안내된 진입 순서 | 실제 발견시간·오클릭률 |
| 입력과 조회의 연결 | 저장 뒤 기록을 다시 찾는 수단이 있는가? | 목록·달력·필터·통계 안내 | 데이터 일관성·대용량 응답시간 |
| 농민과 관리 역할의 연결 | 모바일·웹 또는 관리 포털이 연결되는가? | 동일 계정 안내, 관리 포털 기능 | 실제 권한 차단·동기화 지연 |
| 근거 재사용 | 기록을 범위별로 내보낼 수 있는가? | 내보내기 형식·필터 | 공식 제출 적합성·출력 오류율 |
| 목적 집중도 | 기록 외 기능이 함께 존재하는가? | 커뮤니티·장부·랭킹 등의 존재 | 부가기능 때문에 실제 사용자가 혼란스러운지 |
| 접근성 | 큰 터치·대비·보조기기 사용이 가능한가? | 이번 자료만으로 확정하지 않음 | WCAG 적합성·고령자 성공률 |

“미확인”은 “없음”이 아니다. 안내에 없는 기능을 부재로 단정하지 않는다.

## 3. 1순위: 팜모닝

### 3.1 공식 문서로 확인한 사실

1. [공식 PC 영농일지 출시 안내](https://farmmorning.com/posts/Y29tbXVuaXR5LXBvc3Q6NDAwOTky)는 PC 작성·조회, 달력의 월별 작업, 통계, 영농장부 수입·지출, 내려받기를 안내한다.
2. 같은 안내의 이용 순서는 **웹 접속 및 로그인 → 상단 ‘영농일지’ → 우측 하단 ‘기록하기’**다. 이후 상세 입력 단계나 확인 화면은 이 텍스트로 확정할 수 없다.
3. [2024년 영농일지 개선 안내](https://farmmorning.com/posts/Y29tbXVuaXR5LXBvc3Q6MjQ4NjAy)는 개별 작업을 눌러 보던 방식에서 월간 농작업 현황을 한눈에 보는 방향, 출석체크와 기록 연결을 설명한다.
4. [공개 홈](https://farmmorning.com/)에는 농작업 기록·질문·커뮤니티 콘텐츠가 함께 노출된다. 시장 기능도 비교 맥락에 포함하되, 구매 흐름이나 가격·결제 조건은 이번 조사에서 검증하지 않았다.

### 3.2 장점과 한계의 구분

| 구분 | 내용 | FarmLog 판단 |
|---|---|---|
| 근거 있는 강점 | PC에서도 기록 작성부터 조회·내려받기까지 안내 | 모바일 전용 입력과 관리자용 별도 수기대장을 만들 필요가 없다는 참고 |
| 근거 있는 강점 | 월별 현황·달력·통계 제공 | 기록 후 “이번 달에 무엇을 했는가”를 다시 찾도록 설계 |
| 설계상 주의점 | 종합 농업 서비스의 여러 목적이 공존 | FarmLog의 기록 홈까지 커뮤니티·시장 중심으로 만들면 이번 범위를 넓힐 위험 |
| 미확인 | 실제 작성 필드 수, 저장 성공률, 고령자 수행시간 | “폼이 무겁다”, “느리다”, “일지가 얕다”는 현재 결함 주장 금지 |

### 3.3 채택·회피

- **채택:** 농민이 이해하는 ‘기록하기’, ‘내 기록’, ‘이번 달’이라는 언어. 최근 기록 카드와 날짜·밭 조건. 저장 완료 직후 다시 볼 수 있는 동선.
- **축소 채택:** 달력은 목록 다음의 보조 수단이다. 달력 구현이 필수 기록 흐름을 막지 않도록 후순위로 둔다.
- **회피:** 첫 화면에 출석·랭킹·질문·시장·장부를 같은 비중으로 배치하지 않는다. 이는 팜모닝의 결함 판정이 아니라 FarmLog의 좁은 목적에 따른 선택이다.
- **확장하지 않음:** 수입·지출 내려받기가 있다고 해서 FarmLog MVP에 회계·정산 기능을 추가하지 않는다.

## 4. 2순위: Farmable

### 4.1 공식 문서로 확인한 사실

[웹 보고서 도움말](https://support.farmable.tech/en/articles/6178786-how-do-i-download-my-reports-on-the-web-portal)의 흐름:

`모바일 앱과 같은 자격증명으로 웹 로그인 → Logs → 기간·작업 종류·필지 필터 → Export → PDF/CSV/XLSX 선택 → 다음 화면에서 내보내기`

[Enterprise 시작 안내](https://support.farmable.tech/en/articles/11849034-getting-started-with-enterprise-portal)는 다음을 설명한다.

- 농장 목록과 상태, 지도 보기
- 여러 농장의 작업·수확·판매 기록
- 날짜·농장·종류·상태·농업전문가 기준 정렬/필터
- 필터한 기록 CSV/PDF 출력
- 구성원 초대와 역할 관리, 작업 계획

[모바일 보고서 도움말](https://support.farmable.tech/en/articles/9799238-mobile-reports)은 **모바일에서도 PDF/XLSX 보고서를 만들고 공유할 수 있음**을 안내한다. 날짜·필지 등의 선택과 요약 확인이 포함된다. 따라서 “Farmable은 PC에서만 보고서를 만들 수 있다”는 설명은 사용하지 않는다.

[Enterprise 역할·권한 안내](https://support.farmable.tech/en/articles/15165712-what-are-enterprise-roles-and-permissions)는 역할과 권한 검토용 참고다. 조사에서 관리자·회사정보 관련 설명의 일관성 문제가 확인되어 세부 권한을 정확한 사실로 전재하지 않는다. FarmLog의 권한 설계를 그 표에서 복사하지 않는다.

### 4.2 장점과 한계의 구분

| 구분 | 내용 | FarmLog 판단 |
|---|---|---|
| 근거 있는 강점 | 모바일·웹 같은 계정, Logs 기반 필터·출력 | 역할별 화면이 달라도 기록의 정본은 하나여야 함 |
| 근거 있는 강점 | 관리 포털의 농장·날짜·상태 등 필터 | 관리자는 기록 입력보다 검토할 대상을 좁히는 것이 중요 |
| 근거 있는 강점 | 보고서 생성 전 범위 선택·요약 | 출력 대상·건수·필터를 사용자가 확인하는 패턴 채택 |
| 설계상 주의점 | 다농가·계정·작업배정까지 포함하는 조직형 구성 | 로컬 단일 농장 MVP가 이를 모방하면 인증·보안·운영 범위가 급증 |
| 미확인 | 세부 권한 실제 동작, 요금별 차이, 네트워크 성능 | “권한이 안전하다/취약하다”, “실시간 연동된다”는 단정 금지 |

### 4.3 채택·회피

- **채택:** 농민 입력과 관리자 조회가 같은 일지를 사용. 관리자는 날짜·밭·검토상태로 좁히고 원문과 정정 이력을 본다.
- **채택:** 목록 건수와 출력 범위를 명시하고, 화면의 검토상태를 저장 원장에 근거해 표시.
- **회피:** 회원 초대, 다농가 전환, 조직 역할표, 작업배정, 지도, 판매·재고 기능은 넣지 않는다.
- **핵심 차이:** FarmLog `/admin`은 관리 작업 화면의 이름일 뿐, 인증된 관리자 권한을 뜻하지 않는다. 같은 origin이라는 사실도 접근 통제를 뜻하지 않는다.

## 5. 3순위: 농업ON

### 5.1 공식 문서로 확인한 사실

[웹 개편 공식 공지](https://www.agrion.kr/portal/bbs/selectContentTypeNew.do?bbsId=BBS_ID0000000001&sn=48110&atchFileId=19926b9a18573&pageIndex=1)는 **2025년 9월 18일 오후 6시 웹 적용**을 안내한다.

- 사진과 글이 보이는 카드형 일지
- 이웃 일지와 내 영농일지를 상단 탭으로 전환
- 내 영농일지 현황판: 월간 달력 점 표시, 올해 작성 통계, 영농스타 점수, 이번 달 입출금장부 요약
- 이웃 일지 현황판: 도움지수, 지역·품목 랭킹 등
- 당시 웹 우선 적용이며 앱은 추후 업데이트 예정이라고 명시
- [영농일지 진입 주소](https://www.agrion.kr/portal/farm/diaryMain.do)는 영농일지·입출금장부 관련 서비스의 참고 진입점이다. 로그인 후 실제 작성·장부 처리 과정은 이번 조사에서 검증하지 않았다.

공지의 “메인화면이 복잡했다”, “메뉴를 찾기 어려웠다”는 **개편 전 문제 설명**이다. 2026년 9월 현재도 동일하게 복잡하다는 증거가 아니다. 당시 앱 업데이트 예정이라는 문구 역시 현재 앱이 미개편이라는 증거가 아니다.

### 5.2 장점과 한계의 구분

| 구분 | 내용 | FarmLog 판단 |
|---|---|---|
| 근거 있는 강점 | 내 기록과 이웃 기록을 명시적으로 분리 | 개인 원장과 공개 콘텐츠는 서로 다른 목적임을 UI에서도 구분 |
| 근거 있는 강점 | 카드에 사진·글, 현황판에 달력·연간 통계 | 목록은 내용 파악, 현황판은 회고라는 역할 분리 |
| 설계상 주의점 | 개인 기록과 참여·랭킹 동기가 공존 | FarmLog에서는 기록의 정확성과 수정 가능성을 사회적 점수보다 우선 |
| 미확인 | 현재 모바일 앱 상태, 로그인 이후 전체 동선, 접근성 | 현재도 혼란스럽거나 고령자에게 불편하다는 평가 금지 |

### 5.3 채택·회피

- **채택:** 최근 기록 카드에 날짜·밭·작물·작업을 반복된 순서로 표시. 사진은 선택 정보이며 사진이 없어도 완성된 카드로 보이게 한다.
- **축소 채택:** ‘이번 달 기록’처럼 개인 기록에 한정한 요약. 기록 수를 작업량·성과·인증 적합성으로 해석하지 않는다.
- **회피:** 이웃 공개, 랭킹, 점수, 영농스타. 내부 기록의 기본 공개를 전제하지 않는다.

## 6. 실제 문서 흐름과 FarmLog 제안 흐름을 혼동하지 않는다

| 대상 | 공식 문서에 나온 흐름 | FarmLog가 제안하는 변형 |
|---|---|---|
| 팜모닝 | 로그인 → 영농일지 → 기록하기 | 로컬 `/mvp` → 기록하기 → 밭·작업 → 자세한 내용 → 명시적 확인 |
| Farmable 웹 | 로그인 → Logs → 필터 → 형식 선택 → 출력 | `/admin` → 날짜·밭·검토상태 → 상세·원문 → 내용 확인 또는 보완 필요 |
| 농업ON | 내/이웃 탭, 카드형 일지, 현황판 | 내 기록만 카드 목록으로 제공, 내보내기·회고는 보조 |

FarmLog의 3단계 입력이나 `checked/needs_changes` 검토 방식이 경쟁사의 실제 구현이라고 주장하지 않는다. 이는 기존 FarmLog 원장 계약에 맞춘 **독자 설계**다.

## 7. 공통 UX 설계 원칙으로 환원

1. **한 화면에 주 행동 하나:** 농민 홈의 가장 큰 버튼은 ‘기록하기’. 관리자 홈은 ‘확인할 기록 보기’가 중심이다.
2. **모르는 값은 비워 둔다:** 선택하지 않은 날씨·수량·인원은 `null`. 0이나 ‘문제없음’으로 바꾸지 않는다.
3. **화면은 둘, 기록은 하나:** `/mvp`와 `/admin`은 같은 농민용 일지 원장을 사용한다. 기존 8878 합성 검토실을 연동 관리자로 오인하지 않는다.
4. **저장은 확인 뒤에:** 다음 단계 이동은 저장이 아니다. 마지막 ‘확인하고 저장’ 응답을 받은 뒤에만 저장 완료를 표시한다.
5. **농민 확인과 관리자 확인을 구분:** 내용 확인은 농약 안전성·인증 적합성 확인이 아니다.
6. **정정은 원본 보존:** 기존 기록을 지우지 않고 새 기록을 연결한다. 새 정정본의 관리자 상태는 다시 확인 대기다.
7. **쉽고 밝되 대비는 충분히:** 오프화이트 배경, 세이지 계열 보조색, 짙은 본문. 옅은 초록 글씨나 색만으로 상태를 전달하지 않는다.
8. **재사용 단위는 픽셀이 아니라 규칙:** 필드 정의·상태 이름·검증·일지 카드·오류 표현을 공통 코드로 묶는다. 첫 화면 전체를 범용 컴포넌트에 밀어 넣지 않는다.
